\subsection{TinyAlign - A Transformer Based Projector}

In the paper TinyAlign, Qin et al introduces a transformer based architecture that bridges the audio encoding representation with those of the equivalent text embeddings in the LLM. The framework is a combination of three parts: a projection layers, \textbf{BridgeFormer}, a loss model function, \textbf{EmbedLink} and last instruction tuning.

\subsubsection*{BridgeFormer}

\textbf{BridgeFormer} is the name given to the projection and alignment layer between the audio feature extractor and the LLM. It is a combination of multi-layer perceptron layers, transformer encoders and convolutions. In this framework, the bridgeformer is the only model trained, and the audio feature extractor and LLM is \textit{frozen}. See figure \ref{fig:bridgeformer} for the architecture. BridgeFormer mimics another simple alignment paradigme where you train the projection layer only, hoping to learn a mapping that can utilize the information from the audio feature extractor to the LLM.

This is a mapping from 
$$F_{audio} \in \mathbb{R}^{l\times D_a} \mapsto E_{out} \in \mathbb{R}^{T\times D_l}$$
where $l$ is the sequence length, $D_a$ is the feature dimension of the audio feature extractor, $T$ is the token length which is set and $D_l$ is the LLM embedding dimension size. Usually the sequence lengths are quite large, for example can Whispers sequence length be up to 1500, whereas the token length can be as low as 30. Compare this to the simple projection layer where we use simple downsampling to an output dimension of 150.

The token size, or token length, is determined based on the dataset usually; for example, the token size for the CoRal dataset around 50, enough to properly encode all sentences. If the tokenized trnascription is too long, it is cut off at token 50; otherwise padded with a pad token (usually 0).

The series of computations done in BridgeFormer module can be summed up as the follow:


First a few multilayer perceptrons using a GELU activation and LayerNormalization is employed to project from $D_a$ to a higher dimension input $H$.
$$ E_{in} = MLP_{input}(F_audio) $$

The input is then sent through a few transformer encoder layers with $M$ multi-head self-attentions to process and refine features without reshaping the dimensions.
$$E_{enc} = ENC(E_{in})$$

Afterwards, a convolutional layer is used alongsime an average pooling to reshape the sequence length down to the token length.
$$E_{pool} = Pool(CONV(E_{enc}))$$

Finally, a few more MLPs are used to project down to the LLM embedding dimension size $D_l$.
$$E_{out} = MLP_{output}(E_{pool})$$

The reason that T is chosen, and not something closer to the feature extraction sequence length, lies in how the BridgeFormer module is utilized and trained: \textbf{EmbedLink}.

\subsubsection*{EmbedLink}

The EmbedLink layer is there to ensure cross-modal alignment utilizing the large language model's embedding layer. It does so through the shared embedding space that BridgeFormer projects the audio features into. The insights the authors share is that LLMs text processing relies heavily on its embeddings. Thus if BridgeFormer can transform the audio features into their matching text embeddings from the LLM, alignment can be achieved without the large overhead of LLM inference.
